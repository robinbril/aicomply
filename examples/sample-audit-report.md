## High / medium fails

**EU AI Act**
- `AIA-TRANSP-AI` (medium): widget does not tell users they are talking to an AI. `src/widget/Chat.tsx:120`. Advice: add a clear "AI assistant" disclosure on first message.
- `AIA-DEPLOYER` (high): no record that the upstream provider's instructions for use were reviewed. `docs/` absent. Advice: capture the provider's intended-use docs and confirm AcmeChat stays within them.

**ISO/IEC 42001**
- `AI-TRANSPARENCY` (high): no model/version disclosed to users. `src/widget/Chat.tsx:120`. Advice: publish a short model card.

**ISO/IEC 27001 + 27701**
- `A.8.28-LLM-INPUT` (high): no prompt-injection input handling on retrieved KB content. `src/rag/retrieve.ts:33`. Advice: treat retrieved text as untrusted; constrain tool/permission scope.
- `P.7.4.5-RETENTION` (high): 90-day transcript retention is set but not enforced by a job. `infra/cron/` absent. Advice: add an automated purge and log it.

## Remediation, prioritised

Ordered by severity then weight.

1. **`GDPR-PII-TO-EXTERNAL-LLM`** (critical, w5): add a redaction layer in `src/llm/client.ts` that strips name/email/phone before send; or switch to an EU-region model. Produce a data-flow diagram of prompt egress.
2. **`GDPR-PROCESSOR-DPA`** (critical, w5): sign the provider DPA, store under `/legal/dpa-<provider>.pdf`, reference it in the ROPA.
3. **`AI-RISK-ASSESS`** (critical, w5): write the AI risk assessment; tie mitigations to the two GDPR fixes above.
4. **`AIA-DEPLOYER`** (high, w3): file the provider's intended-use documentation and a one-page conformance note.
5. **`A.8.28-LLM-INPUT`** (high, w3): add untrusted-content handling for RAG inputs; scope tool permissions.
6. **`P.7.4.5-RETENTION`** (high, w3): implement and log the 90-day purge job.
7. **`AIA-TRANSP-AI` / `AI-TRANSPARENCY`** (medium/high): AI disclosure in the widget + a public model card.

## Completeness critic (what was NOT checked)

- **Runtime vs static:** verdicts are from source and config only. No live test of whether redaction actually fires at runtime, or whether the purge job runs. `GDPR-PII-TO-EXTERNAL-LLM` should be re-confirmed against a captured outbound prompt.
- **Training data:** AcmeChat uses a hosted base model; its training-data provenance (`AIA-DATAGOV`, `RID-DATA`) was marked `na` for the deployer role. If Acme fine-tunes later, those flip in-scope.
- **Provider claims taken on trust:** the model card's accuracy/robustness numbers (`AIA-ACCURACY`, `RID-ROBUST`) were accepted as published, not independently tested.
- **Infra out of repo:** IaC under `infra/` was partial; backup (`A.8.13-BACKUP`) and monitoring coverage assume the visible Terraform is complete.
- **Scope uncertainty:** `AIA-FRIA` marked `na` (no high-risk Annex III use found), but the support use case touches no protected-decision area only if Acme never routes complaints to automated resolution. Re-check if that changes.
